# Migrating from Sendbird to Stream Chat React Native: mapping

This mapping of symbols and behaviors has been compiled against `@sendbird/chat`
4.22.7 + `@sendbird/uikit-react-native` 3.12.7 and `stream-chat` 9.50.2 +
`stream-chat-react-native` / `stream-chat-expo` 9.7.0, with the RN UI symbols
re-checked against 9.12.1. Typecheck your work against the currently installed
versions. When the installed Chat RN major differs, translate each Stream symbol
through the migration guide for that pair (chat-versions.md), then confirm it in
the installed major's docs and `node_modules` before writing it.

Import UI symbols from the flavor package (`stream-chat-react-native` or
`stream-chat-expo` - same names) and client symbols from `stream-chat`.

Rows marked **(inferred)** were derived from type definitions, but not verified
in a real-app sample. Take these with extra care.

This mapping lists most common symbols. For the rest, use the local docs
(`getstream docs`) and the installed type definitions.

---

## 1. Init, auth & user

| Sendbird                                                                                        | Stream                                                                                         | Notes / trap                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SendbirdChat.init({ appId, modules, localCacheEnabled })`                                      | `useCreateChatClient({ apiKey, tokenOrProvider, userData, options })`                          | No modules array - one client exposes everything. **`StreamChat.getInstance(apiKey)` is a first-call-wins process singleton NOT keyed by apiKey** - a second call with another key silently returns the first client. Offline cache: section 5.                                                             |
| `SendbirdChat.connect(userId, authToken?)`                                                      | `client.connectUser({ id, name, image }, tokenOrProvider)`                                     | Takes a user object, so profile fields are set at connect. **The token-less userId-only connect has NO Stream equivalent.** `client.devToken(id)` works only while dev tokens are enabled, and a new app has them off - use the pre-minted roster (runbook section 5).                                      |
| `SendbirdChat.setSessionHandler` + `onSessionTokenRequired(resolve, reject)`                    | `tokenProvider: () => Promise<string>` passed as `tokenOrProvider`                             | `resolve(token)` -> `return token`; `reject(err)` -> `throw err`. Stream re-invokes it on expiry - don't push tokens imperatively. **A plain string token never refreshes.** Keep the function stable (module scope or `useCallback`): `useCreateChatClient` reconnects whenever `tokenOrProvider` changes. |
| `onSessionRefreshed` / `onSessionClosed` / `onSessionError`                                     | - (gap)                                                                                        | Fold refresh into the `tokenProvider`; for closed/error, catch the rejection and watch `useChatContext().isOnline`, then log out + `disconnectUser()`.                                                                                                                                                      |
| `ConnectionHandler` / `addConnectionHandler` / `ConnectionState`; `useConnection().reconnect()` | `useChatContext().isOnline` / `connectionRecovering`, or `client.on('connection.changed', cb)` | Reconnection is automatic - delete the reconnect state machine and any `reconnect()` call. A `tokenProvider` keeps re-auth silent across reconnects.                                                                                                                                                        |
| `SendbirdChat.disconnect()`                                                                     | `client.disconnectUser()`                                                                      | The one 1:1 rename. `useCreateChatClient` disconnects on unmount / `userData` change. With offline support, `resetDB()` first (section 5).                                                                                                                                                                  |
| `SendbirdChat.currentUser` / `SendbirdUser`                                                     | `client.user` (+ `client.userID`) / `UserResponse`                                             | Field renames everywhere: `userId` -> `id`, `nickname` -> `name`, `profileUrl` -> `image`, `lastSeenAt` (epoch ms) -> `last_active` (ISO string - convert).                                                                                                                                                 |
| `updateCurrentUserInfo({ nickname, profileUrl })`                                               | `client.partialUpdateUser({ id: client.userID, set: { name, image } })`                        | No dedicated current-user method; `set` / `unset` are field-level.                                                                                                                                                                                                                                          |
| `User.createMetaData` / `updateMetaData` / `deleteMetaData`                                     | `client.partialUpdateUser({ id, set: {...} })` / `{ unset: [key] }`                            | No separate metaData map - custom data is top-level user fields; values widen from string-only to any JSON. Declare them on `CustomUserData` (section 2).                                                                                                                                                   |
| Anonymous / guest connect                                                                       | `client.connectAnonymousUser()` / `client.setGuestUser({ id, name })`                          | A capability Sendbird lacked - NOT a substitute for userId-only login (different permission model).                                                                                                                                                                                                         |
| `SendbirdError` + `SendbirdErrorCode`                                                           | `ErrorFromResponse`                                                                            | (inferred) No exported error-code enum - branch on the numeric `error.code`.                                                                                                                                                                                                                                |

## 2. Channels: model & queries

Sendbird has three channel **classes**; Stream has **one** `Channel` class whose
behavior comes from a server-configured **type string** passed to
`client.channel(type, id?)`.

| Sendbird                                                                                      | Stream                                                                            | Notes / trap                                                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GroupChannel`                                                                                | `client.channel('messaging', id)` (`'team'` for workspace-style)                  | `channel.url` -> `channel.cid` (`type:id`). **Carry the type with the id** - a channel can't be resolved from an id alone. `watch()` loads state and subscribes.                                                                                                                                                              |
| `OpenChannel` + `.enter()` / `.exit()`                                                        | `client.channel('livestream', id)` + `channel.watch()` / `stopWatching()`         | Participants -> `channel.state.watcher_count` / `.watchers`. **`livestream` has read events off** - enable `isLocalUnreadCountEnabled` in the client options or unread counts stop. The type must exist server-side.                                                                                                          |
| `FeedChannel` / `NotificationMessage`                                                         | - (gap)                                                                           | Section 15.                                                                                                                                                                                                                                                                                                                   |
| `isDistinct: true` (dedupe by member set)                                                     | `client.channel('messaging', { members: [...] })` with **no id**                  | Stream derives a deterministic id from the member set; an explicit id disables the dedupe. Members of a distinct channel can't change later.                                                                                                                                                                                  |
| `isSuper` / `isBroadcast` / `isPublic` / `isDiscoverable`                                     | -                                                                                 | Not per-channel flags: scale, broadcast and discoverability are the channel **type's** server-side config + permission grants. The client picks a type; it cannot define one.                                                                                                                                                 |
| `GroupChannelModule.createChannel(params)` / `createChannelWithUserIds`                       | `client.channel(type, id?, { members, ...custom })` then `await channel.create()` | `invitedUserIds` / `operatorUserIds` -> one `members` array (operators are a server-side role change, section 8). **Members must already exist** - Stream doesn't auto-create them. A client-chosen id makes `create()` find-or-create. Set `name` on group channels; leave DMs nameless and derive their title from members. |
| `GroupChannelModule.getChannel(url)`                                                          | `client.channel(type, id)` then `await channel.watch()`                           | Synchronous handle; `watch()` loads state.                                                                                                                                                                                                                                                                                    |
| `GroupChannel.refresh()` / `getChannelWithoutCache`                                           | `channel.query()` or `channel.watch()`                                            | Explicit refetch. Channels don't serialize - rebuild from `(type, id)`.                                                                                                                                                                                                                                                       |
| `GroupChannel.updateChannel(params)`                                                          | `channel.updatePartial({ set: { name, image, ... } })`                            | `coverUrl` -> `image`. `channel.update(data)` is a full replace that wipes unlisted custom fields. **Default `messaging` grants `update-channel` to the owner (`created_by`) and moderators only** - a plain member's edit, allowed in Sendbird, is rejected. Gate the UI on that capability (section 13).                    |
| `GroupChannel.delete()`                                                                       | `channel.delete()`                                                                | **Soft by default; Sendbird's delete is permanent** - a 1:1 port silently changes retention.                                                                                                                                                                                                                                  |
| `GroupChannel.hide()` / `.unhide()`                                                           | `channel.hide(userId?, clearHistory?)` / `channel.show()`                         | No `isHidden()` getter - read `hidden` off the query; list with `queryChannels` filter `{ hidden: true }`.                                                                                                                                                                                                                    |
| `GroupChannel.markAsRead()`                                                                   | `channel.markRead()`                                                              | `<Channel>` marks read on its own - delete manual timers. A no-op unless "Read Events" is on for the channel type.                                                                                                                                                                                                            |
| `GroupChannelListOrder` enum                                                                  | `ChannelSort` object, e.g. `{ last_message_at: -1 }`                              | -                                                                                                                                                                                                                                                                                                                             |
| `GroupChannelFilter` (setter methods), `channelNameContainsFilter` / `nicknameContainsFilter` | `ChannelFilters` object literal                                                   | Search both: `{ $or: [{ name: { $autocomplete: q } }, { 'member.user.name': { $autocomplete: q } }] }` - DMs have no `name`, so a name-only filter misses them. **Annotate it `: ChannelFilters`** or tsc rejects the `$or` array. Never load channels and filter client-side (first page only).                              |
| Channel metadata / meta counters                                                              | `channel.updatePartial` read-modify-write                                         | **Not atomic** - Sendbird's dedicated endpoints were; serialize concurrent writers app-side or move them server-side.                                                                                                                                                                                                         |
| `customType` / `data` / metaData on channels, users, messages                                 | Top-level custom fields                                                           | **Custom fields don't typecheck until declared:** `declare module 'stream-chat' { interface CustomChannelData {...}; interface CustomUserData {...}; interface CustomMessageData {...} }`. Declare `name` on `CustomChannelData` if you filter on it.                                                                         |

## 3. Messages: sending & state

One Stream message shape replaces Sendbird's class hierarchy (`BaseMessage` /
`UserMessage` / `FileMessage` / `MultipleFilesMessage` / `AdminMessage`):
discriminate via `message.type` (`'regular' | 'system' | 'ephemeral' | 'error' | 'reply' | 'deleted'`)
and `message.attachments`.

| Sendbird                                                        | Stream                                                                              | Notes / trap                                                                                                                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `channel.sendUserMessage(params)` -> `MessageRequestHandler`    | `MessageComposer` / `useMessageInputContext().sendMessage()`                        | **Only the UI-context send is optimistic** - `channel.sendMessage()` inserts no pending message. For a custom transport, override `<Channel doSendMessageRequest>` instead of calling the client. |
| `.onPending()` / `.onSucceeded()` / `.onFailed(code)`           | `message.status` + try/catch                                                        | `PENDING` -> `'sending'`, `SUCCEEDED` -> `'received'`, `FAILED` -> `'failed'`. **`SCHEDULED` and `CANCELED` have no equivalent** (section 15).                                                    |
| Optimistic identity: `reqId` swapped for `messageId` on success | One stable id                                                                       | Delete the reqId reconciliation - the same id serves list keys, retry, edit, delete.                                                                                                              |
| `channel.resendMessage(failed)` + `isResendable`                | `useMessagesContext().retrySendMessage(message)`                                    | `MessageList` already renders tap-to-retry on failed messages. Pass the failed `LocalMessage`; no user-vs-file branch.                                                                            |
| `removeFailedMessage(reqId)`                                    | `useMessagesContext().removeMessage(message)`                                       | Local-only cleanup.                                                                                                                                                                               |
| `channel.updateUserMessage(id, params)` / `updateFileMessage`   | `client.partialUpdateMessage(id, { set, unset })` / `client.updateMessage(message)` | Client-level, by id; one path for text and files. Prefer the partial form - the full update can clobber `attachments`.                                                                            |
| `channel.deleteMessage(message)`                                | `client.deleteMessage(messageId)`                                                   | Client-level, by id; **soft by default** (comes back as `type: 'deleted'`).                                                                                                                       |
| `isUserMessage()` / `isFileMessage()` / `isAdminMessage()`      | `message.type` + `message.attachments.length`                                       | `AdminMessage` -> `type === 'system'` (no sender; override `MessageSystem` to style it).                                                                                                          |
| `customType` / `data`                                           | Top-level custom fields, or a custom `attachment.type`                              | Nested JSON is stored as-is (no stringify). Render custom types through the `UnsupportedAttachment` override.                                                                                     |
| `silent: true`                                                  | `sendMessage(message, { skip_push: true })`                                         | Sendbird's silent message is persisted-but-quiet; Stream's `ephemeral` is transient - **don't** map silent to ephemeral.                                                                          |
| Threads: `msg.getThreadedMessagesByTimestamp(ts, params)`       | `channel.getReplies(parentId, { limit, id_lt })`                                    | Timestamp anchor -> id cursor; the response has no bundled parent. Send replies with `parent_id` (+ `show_in_channel`).                                                                           |
| `ReplyType` enum (`NONE` / `ALL` / `ONLY_REPLY_TO_CHANNEL`)     | - (gap)                                                                             | `show_in_channel: true` per reply; no toggle hides all replies from the list.                                                                                                                     |
| `channel.copyMessage(msg, target)`                              | - (gap)                                                                             | No server copy - read the source and `target.sendMessage({ ...content })`.                                                                                                                        |
| `channel.translateUserMessage(msg, langs)`                      | `client.translateMessage(messageId, language)`                                      | One call per language. **Read the live `message.i18n`, not the response** - the response nests the message under `.message`, so `res.i18n` typechecks but is `undefined`.                         |
| `useMentionTextInput` / `MentionedUser`                         | Composer mentions middleware -> `mentioned_users`                                   | (inferred) `MessageComposer` captures @-mentions and shows suggestions itself - drop the hand-rolled range/user bookkeeping.                                                                      |

## 4. Attachments & media

| Sendbird                                                                  | Stream                                                                                    | Notes / trap                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FileMessage` / `MultipleFilesMessage` / `sendMultipleFilesMessage`       | One message with `attachments: Attachment[]`                                              | `type: 'image' \| 'file' \| 'video' \| 'audio'` per entry; images and files mix freely in one message.                                                                                                                                              |
| `channel.sendFileMessage(params)` - uploads AND sends atomically          | `channel.sendImage` / `sendFile` (CDN upload) then `channel.sendMessage({ attachments })` | **Two steps.** In practice don't hand-roll it - `MessageComposer`'s `AttachmentManager` owns pick -> upload -> attach -> send and the per-file state.                                                                                               |
| `onFileUploaded` progress callbacks                                       | `AttachmentManager` upload state                                                          | `'uploading' \| 'finished' \| 'failed' \| 'blocked' \| 'pending'` per file, not a callback.                                                                                                                                                         |
| `UploadedFileInfo`                                                        | One `Attachment`                                                                          | `url` -> `asset_url` / `image_url`, `fileName` -> `title`, `fileSize` -> `file_size`, `type` -> `mime_type`.                                                                                                                                        |
| `thumbnailSizes` -> `Thumbnail[]`                                         | Single `thumb_url`                                                                        | No server-side multi-size thumbnails. For video, generate a poster yourself and set `thumb_url` before sending.                                                                                                                                     |
| `AppInfo.uploadSizeLimit` / file-count limit                              | `AttachmentManager` config (`maxNumberOfFilesPerMessage`)                                 | Compression or other pre-upload work goes in `<Channel doFileUploadRequest>`, not a send param.                                                                                                                                                     |
| `cancelUploadingFileMessage`                                              | `AttachmentManager.cancelAttachmentUploads()`                                             | For manual uploads abandoned before sending, `channel.deleteImage(url)` / `deleteFile(url)` to avoid orphaned CDN files.                                                                                                                            |
| Voice messages (`enableVoiceMessage: true`)                               | `<Channel audioRecordingEnabled>` + built-in recorder/player                              | **Off by default** - without the prop the composer shows no mic and the feature silently vanishes. Needs an audio package (`expo-audio` on Expo SDK 53+, per the Installation page otherwise). The simulator has no mic - recording needs a device. |
| `FileViewer`                                                              | `ImageGallery` (mounted by `OverlayProvider`)                                             | Images and video only; other files open via the platform.                                                                                                                                                                                           |
| `platformServices` (`createNativeFileService`, `createExpo*Service`, ...) | -                                                                                         | Dropped - Stream RN handles media, files, clipboard and audio internally.                                                                                                                                                                           |

## 5. Events & real-time

| Sendbird                                                                                                                    | Stream                                                                                                             | Notes / trap                                                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `new GroupChannelHandler({ onMessageReceived, ... })` + `addGroupChannelHandler(key, h)` / `removeGroupChannelHandler(key)` | `client.on(type, cb)` / `channel.on(type, cb)` -> `{ unsubscribe }`                                                | Keyed registration -> retained unsubscribe handle called in the effect cleanup. Events arrive only for **watched** channels.                                                                                                                        |
| Named typed callbacks (`onMessageReceived`, `onTypingStatusUpdated`, `onUserMarkedRead`, `onReactionUpdated`, ...)          | One `(event) => void` per string type (`'message.new'`, `'typing.start'` / `'typing.stop'`, `'message.read'`, ...) | Narrow by `event.type`. One `onTypingStatusUpdated` = `typing.start` + `typing.stop`; one `onReactionUpdated` = `reaction.new` / `.updated` / `.deleted`.                                                                                           |
| List updates on receive                                                                                                     | Automatic                                                                                                          | `MessageList` re-renders from socket events itself - **don't hand-wire listeners to update the list**. Subscribe only for side effects (badges, analytics, navigation).                                                                             |
| `MessageCollection` + `setMessageCollectionHandler` (`onMessagesAdded/Updated/Deleted`)                                     | `<Channel><MessageList/></Channel>`, or `channel.watch()` + `channel.state.messages` + `channel.on(...)` headless  | No collection object. `collection.dispose()` -> unmount, or call the retained `unsubscribe()`s.                                                                                                                                                     |
| `MessageCollectionInitPolicy.CACHE_AND_REPLACE_BY_API` (`onCacheResult` + `onApiResult`)                                    | `await channel.watch()`                                                                                            | No cache-first callback pair. With offline support the SDK renders local state first and reconciles transparently.                                                                                                                                  |
| `onHugeGapDetected` + changelog APIs                                                                                        | Automatic reconnect recovery                                                                                       | Delete the changelog rebuild.                                                                                                                                                                                                                       |
| `UserEventHandler` (`onTotalUnreadMessageCountChanged`, ...)                                                                | `client.on(cb)` reading `event.total_unread_count`                                                                 | Block state via `client.getBlockedUsers()`.                                                                                                                                                                                                         |
| `FeedChannelHandler`                                                                                                        | `notification.message_new` / `notification.added_to_channel`                                                       | `notification.*` events fire for member channels you don't watch.                                                                                                                                                                                   |
| `localCacheEnabled` / `initializeCache`                                                                                     | `<Chat enableOfflineSupport>` + `@op-engineering/op-sqlite`                                                        | Native SQLite - needs a native rebuild. `useCreateChatClient` returns the client only after connect resolves; to render from the DB while offline, create the client yourself and call `connectUser` without awaiting it before rendering `<Chat>`. |
| `LocalCacheConfig` (`maxSize`, `clearOrder`, `enableAutoResend`)                                                            | -                                                                                                                  | Self-managed DB, no size/eviction knobs; queued sends, deletes and reactions resend on their own. At-rest encryption is `<Chat getOfflineDbEncryptionKey>` (needs an op-sqlite SQLCipher build).                                                    |
| `clearCachedData()` / `clearCachedMessages(url)`                                                                            | `await client.offlineDb?.resetDB()`                                                                                | DB-wide only. **Call it on sign-out before `disconnectUser()`** or the next user sees cached data from the previous one.                                                                                                                            |

| Sendbird                                                              | Stream                                                                                          | Notes / trap                                                                                                                                                                                         |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `startTyping()` / `endTyping()` + app timeout                         | `channel.keystroke()` (self-throttles, auto-emits stop)                                         | Delete the manual timer; `MessageComposer` calls `keystroke()` for you.                                                                                                                              |
| `typingIndicatorThrottle` (ms)                                        | - (gap)                                                                                         | Throttled internally.                                                                                                                                                                                |
| `getTypingUsers()` / `TypingIndicatorType`                            | `useTypingContext().typing`; `<TypingIndicator>` auto-rendered in `MessageList`                 | In channel-list rows use `useChannelTypingState({ channel })`. Filter out your own id.                                                                                                               |
| Presence: `connectionStatus` polled on an interval                    | `client.queryUsers(filter, sort, { presence: true })` once + `user.presence.changed` events     | Push replaces the poll - delete the interval. Presence is tracked only for users queried or watched with presence, else `online` / `last_active` go stale.                                           |
| Presence UI baked into UIKit avatars                                  | `OnlineIndicator`, `useUserActivityStatus(user)`, `useChannelOnlineMemberCount(channel)`        | **`useIsOnline` is your own connection, not another user's presence.**                                                                                                                               |
| `getReadMembers()` / `getReadStatus()` / `getUnreadMembers()`         | `channel.state.read` (keyed by user id)                                                         | Reader of a message = `read[userId].last_read >= message.created_at`. Requires "Read Events" on the channel type.                                                                                    |
| `channel.unreadMessageCount` / `unreadMentionCount` (live props)      | `channel.countUnread()` / `countUnreadMentions()` (methods)                                     | Global totals via `client.getUnreadCount()` and `event.total_unread_count`.                                                                                                                          |
| `getDeliveryStatus` / `getUndeliveredMemberCount` / `markAsDelivered` | `channel.messageReceiptsTracker` + `message.delivered`; rendered by the default `MessageStatus` | Enable `delivery_events` on the channel **type**; the SDK marks delivery itself - drop `markAsDelivered`. `MessageStatus` shows sent -> delivered (grey double check) -> read (accent double check). |

## 7. Pagination: every stateful cursor dies

Sendbird queries are stateful objects (`.next()` / `.load()` / `.hasNext`);
Stream calls are stateless. This is the largest mechanical-but-not-codemod-safe
transform in the migration. In UI, the prebuilt lists paginate for you.

| Sendbird query                                                                       | Stream call                                                                                                                                    | Paging                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `createMyGroupChannelListQuery` / `GroupChannelCollection`                           | `<ChannelList>` (`useChannelsContext().loadNextPage` / `hasNextPage`); raw: `client.queryChannels({ members: { $in: [me] } }, sort, options)`  | offset = `channels.length`. Prefer `<ChannelList>` - it dedupes by `cid`; offset pages over a reordering list skip or duplicate rows.                                                                                    |
| `createPublicGroupChannelListQuery`                                                  | `queryChannels` with a discoverable-type filter                                                                                                | offset/limit                                                                                                                                                                                                             |
| `OpenChannelListQuery`                                                               | `queryChannels({ type: 'livestream', ... })`                                                                                                   | offset/limit                                                                                                                                                                                                             |
| `MessageCollection.loadPrevious()` / `loadNext()`, `PreviousMessageListQuery.load()` | `MessageList` (`usePaginatedMessageListContext().loadMore` / `loadMoreRecent`); raw: `channel.query({ messages: { limit, id_lt: oldestId } })` | id cursor, not timestamp                                                                                                                                                                                                 |
| `startingPoint` timestamp jump                                                       | `channel.state.loadMessageIntoState(messageId)`, or `channel.query({ messages: { id_around, limit } })`                                        | Message-id anchor. By time: `{ created_at_around: <ISO> }` - convert epoch ms first.                                                                                                                                     |
| `createApplicationUserListQuery`                                                     | `client.queryUsers(filters, sort, { offset, limit })`                                                                                          | `userIdsFilter` -> `{ id: { $in } }`, `nicknameStartsWithFilter` -> `{ name: { $autocomplete } }`. **An empty filter returns no users for a user token, silently** - always pass a real condition (e.g. the roster ids). |
| `BannedUserListQuery`                                                                | `client.queryBannedUsers({ channel_cid? }, sort, { offset, limit })`                                                                           | Read `response.bans[]`.                                                                                                                                                                                                  |
| `createOperatorListQuery`                                                            | `channel.queryMembers({ channel_role: 'channel_moderator' }, sort, options)`                                                                   | -                                                                                                                                                                                                                        |
| `createMemberListQuery`                                                              | `channel.queryMembers(filter, sort, options)`                                                                                                  | `MemberStateFilter.INVITED` / `JOINED` -> filter on `invited`.                                                                                                                                                           |
| `MessageSearchQuery`                                                                 | `client.search(channelFilters, query, { limit, next })`                                                                                        | `next` cursor, not `hasNext`.                                                                                                                                                                                            |
| `createThreadedParentMessageListQuery`                                               | `client.queryThreads(options)`                                                                                                                 | Returns `Thread` objects (cross-channel inbox).                                                                                                                                                                          |
| Thread replies                                                                       | `channel.getReplies(parentId, { limit, id_lt })`                                                                                               | id cursor                                                                                                                                                                                                                |
| `ScheduledMessageListQuery`                                                          | -                                                                                                                                              | Feature gap (section 15).                                                                                                                                                                                                |

Sendbird's `hasNext` is server-authoritative; Stream's equivalent is a
count-vs-limit heuristic (a short page = end). A `while (query.hasNext)` drain
loop doesn't translate - tighten the server-side filter so the set fits in one
or two pages instead.

## 8. Membership, roles & moderation

**The most dangerous mismap in the whole migration lives here** - see the
`muteUser` row.

| Sendbird                                                              | Stream                                                                          | Notes / trap                                                                                                                                                                                          |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `channel.invite(users)` / `inviteWithUserIds(ids)`                    | `channel.inviteMembers(ids)`; invitee calls `acceptInvite()` / `rejectInvite()` | Pass ids. Use `addMembers` instead if the app auto-accepted invites. Invitees must already exist.                                                                                                     |
| `channel.join(accessCode?)`                                           | `channel.addMembers([client.userID])` (private) or `watch()` (open)             | No self-join or access code - access moves to channel-type permissions.                                                                                                                               |
| `channel.leave()`                                                     | `channel.removeMembers([client.userID])` (+ `stopWatching()`)                   | -                                                                                                                                                                                                     |
| Remove another member (server-only in Sendbird)                       | `channel.removeMembers(ids)`                                                    | Client-side in Stream, subject to the `update-channel-members` capability.                                                                                                                            |
| `myRole: Role` (`OPERATOR` \| `NONE`) / `Member.role`                 | `channel.state.membership.channel_role` + own capabilities                      | `OPERATOR` -> `'channel_moderator'`. **There is no `owner` role** - the owner is `channel.data.created_by`. Gate UI on capabilities, not role strings (section 13).                                   |
| `addOperators(ids)` / `removeOperators(ids)`                          | `channel.addModerators(ids)` / `demoteModerators(ids)` - **server-side only**   | A user token can't grant or revoke roles (`addModerators`, `demoteModerators`, `assignRoles`, `addMembers` with a role). Do it from a backend and record the gap; keep an Operators screen read-only. |
| `channel.muteUser(user, duration?)` - **operator-enforced silencing** | timed `channel.banUser(id, { timeout, reason })`                                | **`client.muteUser` is the WRONG target**: it is a personal mute that doesn't stop the target from posting. Reserve it for an "I don't want to hear from X" feature. **Convert seconds -> minutes.**  |
| `blockUser(user)` - **global**                                        | `client.blockUser(id)` - **DM-only**                                            | Blocked users still post in shared group channels - filter client-side or moderate. Unblock is `client.unBlockUser(id)` (capital B); read via `client.getBlockedUsers()`.                             |
| `channel.report(category, desc)`                                      | - (gap)                                                                         | Flag a representative message instead.                                                                                                                                                                |

## 15. Feature gaps - no Stream equivalent, decision required

Each needs an explicit user decision (substitute / rebuild app-side / drop)
recorded in the parity ledger and routed through the runbook's gap checkpoint
(section 3) - never a silent TODO.

| Sendbird feature                                                                                                   | Status                                                      | Closest substitute                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **`FeedChannel`** / Notifications (feed, categories, templates, impression analytics)                              | No stream-chat equivalent                                   | Admin-post-only `messaging` channel rendered read-only (loses categories and analytics), or Stream's separate Feeds product. |
| **Scheduled messages** (`createScheduledUserMessage`, `sendScheduledMessageNow`, list query, `SCHEDULED` status)   | No client scheduled send                                    | Server-side job that sends at the target time; drafts (`channel.createDraft`) save but **never auto-send**.                  |
| **Report a channel** (`channel.report`)                                                                            | No channel-flag endpoint                                    | Flag a representative (e.g. latest) message via `client.flagMessage`.                                                        |
| **`ReportCategory` enum**                                                                                          | Free-text `reason` only                                     | Fold the category label into the reason; build your own picker.                                                              |
| **`copyMessage`**                                                                                                  | No server copy                                              | Re-send content to the target channel.                                                                                       |
| **Operator promote/demote from the client**                                                                        | Server-side only                                            | Backend endpoint; read-only Operators screen in the app.                                                                     |
| **Free-text "type any name" login** (userId-only connect)                                                          | Stream always needs a signed token                          | Fixed pre-minted roster for dev; a backend token endpoint for real logins.                                                   |
| **Session lifecycle callbacks** (`onSessionRefreshed` / `Closed` / `Error`)                                        | -                                                           | `tokenProvider` error handling + `isOnline`.                                                                                 |
| **Recurring DND quiet hours** (weekly + timezone); **runtime push template switch**; push click/delivery analytics | One-shot snooze only; templates are Dashboard/server config | Schedule `setPushPreferences` snooze windows; `skip_push` per message; analytics in your notification handlers.              |
| **`ReplyType` list-visibility enum**                                                                               | -                                                           | `show_in_channel` per reply.                                                                                                 |
| **Server-side multi-size thumbnails**                                                                              | Single `thumb_url`                                          | Resize client-side; generate video posters yourself.                                                                         |
| **Atomic meta counters / meta arrays**                                                                             | Read-modify-write only                                      | Serialize writers app-side or move them server-side.                                                                         |
| **CSAT / message feedback / forms; AI-Agent / Desk conversations** (handoff, resolution)                           | No primitive                                                | A `messaging` channel + your own backend for status; feedback as a reaction or custom message data.                          |
| **Friends / social graph** (`FriendListQuery`)                                                                     | No concept                                                  | Model relations in your own backend; approximate with `queryUsers` / membership.                                             |
| **UIKit atoms and dialogs** (`ProfileCard`, `useToast`, `useBottomSheet`, `usePrompt`, ...)                        | No drop-in set                                              | Build with RN core; Stream's overlays cover only its own menus, picker and gallery.                                          |
